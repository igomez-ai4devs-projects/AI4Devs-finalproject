# [C1] T-C1-10 · Requester intake form — plain language, mobile, WCAG 2.1 AA

## Context

`US-C1-01` requires the requester-facing intake form to use plain language with no untranslated ITSM vocabulary (`NFR-USE-01`), to be operable on a mobile device (`NFR-USE-04`), to meet WCAG 2.1 AA, and to state for every validation error what happened and what to do next (`NFR-USE-05`).

**Blocked by finding F29 — not touched by this pass; the Product Owner stands by this backlog's reading and will close it with a PRD clarification.** `FR-INC-01` is ambiguous about whether a requester may set the *structured* competition subject. This backlog reads it as: **requesters supply free text, agents set the structured reference** (`US-C1-01`, `US-C1-03`). The form is built to that reading, with a free-text competition description and no structured subject picker. If the Product Owner confirms the opposite reading, this form and the permissions of `T-C1-14` and `T-C1-16` change. The rest of the form is unaffected and buildable now.

**Two deviations the user has explicitly accepted for delivery slice 1, and one narrowing from "echo" to "redirect":**

1. **Design system deferred (−0.5h), accessibility is not.** No composition of `libs/incident/ui`/`libs/shared/ui` primitives — those libraries are not part of this slice. Hand-written semantic HTML directly: `<label for>` on every control, `<fieldset>`/`<legend>` grouping related fields, `aria-describedby` linking a field to its error text, `role="alert"` on the error summary. This meets the same WCAG 2.1 AA bar the design system would have; it is not a reduced bar, only a different building method for now.
2. **i18n deferred to a constants file.** Every string lives in one exported constants file for this feature (the same file `T-C1-101` establishes), never inline in the template and never through `nestjs-i18n`/Transloco yet — the user has explicitly accepted this debt against `CLAUDE.md` §3.
3. **"See it" is a redirect, not an echo.** A successful submission navigates to the detail route at the returned reference (`T-C1-101`) rather than showing the reference inline on the intake form — an echo of the `POST` shows what was typed, not what was persisted, which is the whole reason `T-C1-99`/`T-C1-100`/`T-C1-101` exist.

**Known-pending criterion — do not delete.** AC3 below cites the `aria-live` region from `T-C10-14`. `T-C10-14` (`libs/shared/ui`'s overlay/announcer primitive) is not part of this delivery slice — deferred along with the rest of the design system by deviation 1. **This criterion will not pass until `T-C10-12`/`T-C10-13`/`T-C10-14` land.** It stays in this ticket because it is a legitimate requirement this cut defers, not one this cut satisfies; whoever implements this ticket now must know it is left pending on purpose, not silently unmet.

## Scope

- Routed intake page in `libs/incident/feature`; hand-built semantic HTML and component-scoped SCSS, no `libs/incident/ui` or `libs/shared/ui` primitive, no third-party component library (deviation 1 above).
- Reactive Form bound to the requester DTO of `T-C1-08`; `OnPush`; built-in control flow.
- Every user-facing string sourced from the one exported constants file per deviation 2 above; no hardcoded literal in the template, and no `nestjs-i18n`/Transloco call either — that infrastructure is not part of this slice.
- Free-text field for competition context; **no** Impact, Urgency, Priority or competition-flag control anywhere in the form.
- Error summary and per-field messages that state the remedy — native `role="alert"` and `aria-describedby` for now (deviation 1); the `aria-live` region from `T-C10-14` is the pending criterion above, not built here.
- On success, navigate to the detail route at the returned reference (deviation 3) — no reference display on this form itself.
- Out of scope: knowledge suggestions (`T-C1-90`); the scope-rule redirect surface (`T-C1-88`); the structured subject picker (`T-C1-16`); any `libs/shared/ui`/`libs/incident/ui` primitive.

## Acceptance criteria

**Given** a requester on the intake form **When** it is rendered **Then** it presents no Impact, Urgency, Priority or competition-in-progress control, and the page source contains no such input at any breakpoint.

**Given** a keyboard-only user on a 360px viewport **When** they complete and submit the form **Then** every control is reachable and operable without a pointer, no horizontal scrolling is required, and focus is managed across the submission.

**Given** a submission that fails validation **When** the response returns **Then** each message states what happened and what to do next in the active language, the error summary is exposed via `role="alert"`, and is announced through the `aria-live` region from `T-C10-14` — **pending**, see the note above; not runnable until `T-C10-12`/`T-C10-13`/`T-C10-14` exist.

**Given** a successful submission **When** it returns **Then** the shell navigates to the detail route at the returned reference (`T-C1-101`) — the form itself never displays the reference or the persisted state.
