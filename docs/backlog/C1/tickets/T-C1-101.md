# [C1] T-C1-101 · Incident detail component — plain HTML, reference-routed

## Context

The client half of `T-C1-100`. `US-C1-01`'s "see it" is satisfied here: a route at the reference, reached by redirect from a successful intake submission, rendering exactly the persisted state — never the form the requester just filled in.

**Two deviations the user has explicitly accepted for this slice, both recorded here because this is where they are visible to whoever implements it:**

1. **Design system deferred, accessibility is not.** No composition of `libs/shared/ui`/`libs/incident/ui` primitives yet — those libraries are not part of this slice. The template is hand-written semantic HTML (`<dl>`/`<dt>`/`<dd>` or an equivalent native structure for the field list, a heading hierarchy, `role="status"` for the loading state) meeting the same accessibility bar the design system would have provided. This component's **logic is permanent**; only its markup gets re-skinned once the design system lands — that restyling is not a rewrite of this ticket.
2. **i18n deferred to a constants file, not embedded strings.** Every user-facing string in this component (labels, the not-found message, the loading state) lives in one exported constants file per feature — `libs/incident/feature/src/lib/i18n-strings.ts` (or the equivalent path once the library exists) — imported by the template, never written inline in it. This is the single location `T-C1-100`'s not-found message and any later Transloco migration both read from; **do not duplicate a string literal in the template that could instead reference this file.**

## Scope

- Routed detail component in `libs/incident/feature`, resolving the reference from the route and calling the GET method `T-C1-09`'s adjustment adds to `IncidentApiService`.
- Explicit, always-rendered states: loading, not-found, loaded — never an undefined intermediate state.
- Plain semantic HTML template (see deviation 1 above); component-scoped SCSS limited to layout, no design-token dependency yet.
- The one exported strings file per deviation 2 above; every string in this component's template is a reference into it.
- `OnPush`; no `[(ngModel)]`; signals for the three states.
- Out of scope: any editing action on the Incident; any navigation *to* this route other than the post-intake redirect (`T-C1-10`'s adjustment); the design-system restyle, which is a separate, later ticket by definition.

## Acceptance criteria

**Given** a successful intake submission **When** the redirect completes **Then** the detail route renders the just-created Incident's persisted state, not the values the requester typed.

**Given** a reference with no matching Incident **When** the route is visited directly **Then** an explicit not-found state renders — never a blank screen or an unhandled error.

**Given** the rendered detail view **When** it is inspected with a screen reader **Then** the field list is structured with native semantic elements (not a sequence of unlabelled `<div>`s) and the loading state is announced via `role="status"` — meeting the accessibility bar without any `libs/shared/ui` primitive.

**Given** the component's template **When** it is grepped for a quoted, user-facing string **Then** every match is a reference into the one exported strings file, never a literal.
