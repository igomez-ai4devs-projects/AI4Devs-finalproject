# [C1] T-C1-11 · `LogIncidentOnBehalfUseCase` — reporter, contact channel and acting actor

## Context

`US-C1-02` requires an agent logging on behalf of a caller to produce an Incident whose **reporter is the caller**, whose contact channel records how the report arrived, and whose **acting agent is recorded separately** as the actor of the creation. It also requires that an agent — unlike a requester — may set Impact, Urgency and the competition-in-progress flag at logging, because the agent holds the permission for priority-bearing fields.

The origin channel taxonomy itself belongs to `C11` (`FR-OMN-01`/`FR-OMN-02`); this use case records the channel value it is given and does not define the channel catalogue.

**Carries the `logged_by_user_id` migration (ADR-014 / `DATA-MODEL.md` §8.5).** `T-C1-06`'s table-creating migration deliberately excludes this column — it is introduced by "agent-logged intake (FR-OMN-01)", which is this ticket. Nullable, `NOT NULL` never required, no backfill (every row already existing has no acting agent distinct from its reporter, which is what `NULL` already means).

**Resolved this second pass — the earlier "flagged, not resolved" build-order question.** This ticket's own last acceptance criterion has an agent recording Impact and Urgency **at logging time**, yet `base_impact`/`urgency` and the aggregate mutators that write them are `T-C1-30`'s (block D, built after this block B ticket) — and `T-C1-06`'s mapper (ADR-014 rule 4) actively **refuses to save** an aggregate whose not-yet-introduced slots are non-empty, so this use case cannot call a mutator that does not exist yet without breaking that guarantee. The two options this ticket's first pass left open are resolved as follows: **this ticket's command DTO accepts Impact and Urgency from the agent and validates/authorizes them, but does not yet forward them to the aggregate** — until `T-C1-30` ships, they are accepted and silently not persisted, never rejected outright, and the Incident is created exactly as `T-C1-06`/`T-C1-07` already produce it (no category, no assessment, flag unset). This is a deliberate, explicit, temporary narrowing of this ticket's own AC4, not a silent gap: once `T-C1-30`'s mutators exist, wiring this already-accepted command shape to them is that ticket's own follow-up, not a change to this ticket's contract or route. **Reported as a finding for the architect:** `T-C1-30`'s own ticket does not currently mention picking up `T-C1-11`'s dormant command fields — confirm that wiring lands there (or name a successor ticket) so the values this ticket already collects are not silently dropped forever.

## Scope

- `LogIncidentOnBehalfUseCase` in `libs/incident/application`, authorizing the acting actor for the agent-intake permission.
- Reporter resolved by identifier from the command and required to exist; a missing reporter is a typed domain error, never an anonymous ticket (`NFR-SEC-01`).
- Distinct persistence of reporter and acting actor, so the two are separable in the activity history.
- **Migration** adding `logged_by_user_id uuid NULL` (soft ref → `iam.iam_user`) to `incident_ticket`. No backfill; the column is simply absent from every pre-existing row's meaning.
- Mapper extension: `loggedByUserId` moves from an unrepresentable slot to a real nullable read/write; no change to `T-C1-06`'s handling of the columns still absent (category, assessment, flag).
- Agent-supplied assessment fields accepted on this path only; the flag write itself delegates to the single write path of `T-C1-43` rather than being duplicated here.
- Out of scope: the agent UI (`T-C1-12`, `T-C1-13`); the channel catalogue (`C11`); the flag use case and its own migration (`T-C1-43`).

## Acceptance criteria

**Given** an agent logging for a registered caller **When** the use case executes **Then** the persisted reporter is the caller, the acting actor is the agent, and the contact channel is recorded; the three are distinguishable when the Incident is read.

**Given** a command naming a reporter that does not exist **When** the use case executes **Then** it raises a typed domain error and creates nothing — no anonymous or placeholder reporter is created.

**Given** an actor without the agent-intake permission **When** they invoke this use case **Then** it is denied with the typed authorization error that maps to `403`, and nothing is persisted.

**Given** an agent supplying Impact and Urgency at logging, before `T-C1-30` ships **When** the Incident is created **Then** the command is accepted and authorized, no Priority is accepted directly from the command, and the persisted Incident is unassessed exactly as `T-C1-06`/`T-C1-07` already produce it — no mapping error is raised and nothing is silently corrupted. **Once `T-C1-30` ships**, the same command shape persists the supplied Impact and Urgency and Priority derives from them, with no change to this route or its DTO.

**Given** the migration **When** it is run and reverted **Then** it succeeds both ways, leaves no residual object, and requires no backfill.
