# [C1] T-C1-49 · Incident state model over the shared `StateModel` primitive

## Context

`US-C1-15` requires exactly the states of `FR-INC-06`: `New`, `Assigned`, `In Progress`, `Pending` with **three distinguishable reasons** (customer, third party, change), `Resolved`, `Closed` and `Cancelled`. It requires the model to be realized through the **`StateModel` primitive in `libs/shared/domain`** rather than a workflow god-context (`C12`, ADR-001), and every state change to publish an event with actor, previous state and new state (`FR-AUD-01`).

`StateModel` is delivered by `C10` (`T-C10-10`) and configured per context by `C12`. **Do not build a workflow engine here** — this ticket instantiates the primitive for Incidents.

**Resolved this second pass — the two extra exit-from-`New` gates are now `FR-INC-19` (PRD §14.10), landed in the same pass as ADR-014.** What this ticket's first pass carried as an unnumbered Product Owner decision is now text: "In addition to the category required by FR-INC-03, the system MUST prevent an Incident from leaving the `New` state unless Impact and Urgency have been assessed (and therefore Priority derived, FR-INC-04) and an affected service has been recorded." In addition to the categorization gate of `T-C1-25`: (1) Impact **and** Urgency must both be assessed before an Incident may leave `New`; (2) the affected Service must be set before an Incident may leave `New`. Both compose at the same `transitionTo()` call as the categorization gate, so this ticket builds them alongside it rather than leaving them to a second guard that would re-open the same method. **A build-order consequence follows directly from the wording ("Impact and Urgency have been assessed"):** these two gates cannot be exercised — the aggregate has nothing to check — until `T-C1-30`'s assessment mutators and columns exist, and the categorization gate they compose with needs `T-C1-21`'s `category_id`. This ticket therefore cannot be the first to ship a working exit-from-`New` transition; it lands in block F, after blocks C and D, which the existing block order already respects.

**The domain identifies `New` by the non-configurable state category `new` (M17), never by a state's configurable code.** `state_category_enum` gains a sixth value, `new`, reserved for the initial state and no other (`DATA-MODEL.md` §3.5/§8.1, `ck_incident_workflow_state_new_is_initial` in `T-C1-50`). This aggregate's transition guard must read the state's `category`, not its code or display label, so that no lifecycle configuration can rename or reconfigure its way out of the gate — exactly what `FR-INC-19`'s "whatever lifecycle transitions are configured… configuration can add conditions, never remove these" requires.

**Story attribution (F32, this pass).** `docs/backlog/C1/user-stories.md` now gives `FR-INC-19` its own story, `US-C1-33`, rather than treating it as a restatement of `US-C1-15` or `US-C1-24`. This ticket's `story:` front matter **stays `US-C1-15`**: the majority of its scope — instantiating `StateModel` for Incidents, the full `FR-INC-06` state enumeration, terminal-state protection and `IncidentStateChanged` — is that story's own build, and the ticket's title and identity have always been the state model, not the gate. The two new gates this ticket also carries (Impact/Urgency assessed, affected Service set) are `US-C1-33`'s acceptance criteria — AC1, AC2 and AC3 below trace to `US-C1-33`, not `US-C1-15` — cross-referenced here rather than reparented, per the same reasoning `T-C1-73`'s own note applies to the assignment half.

**The untriaged-period rule (`FR-INC-20`) is out of this ticket, on its own new ticket.** An Incident must not be able to remain in `New` with no category indefinitely. The PRD now states this as `FR-INC-20` and records its value and default action on expiry as **PRD assumption A11**, deliberately unfixed. This ticket does **not** invent a deadline or a sweep; that work is `T-C1-102` (new this pass), which depends on `state_category = 'new'` existing (this ticket) and is itself dependent on A11 for its production configuration value, never on this ticket's own gate.

## Scope

- `IncidentState` declared over the shared `StateModel` primitive, with the three Pending reasons as distinguishable states rather than a free-text reason field.
- `transitionTo()` on the aggregate validating against the model and raising a typed domain error naming the current state and the attempted target on refusal.
- `IncidentStateChanged` domain event carrying actor, previous state, new state and the `ClockPort` timestamp.
- Terminal-state protection: `Closed` and `Cancelled` permit only the transitions the configuration explicitly allows — reopening is a configured transition, never implicit.
- Composition with the categorization gate of `T-C1-25` and the resolution gate of `T-C1-54`.
- **New:** an Impact-and-Urgency-assessed gate and an affected-Service-set gate, both refusing exit from `New` with a typed domain error naming the missing input(s), composed at the same `transitionTo()` call as the categorization gate.
- Out of scope: the transition configuration store (`T-C1-50`); the use case (`T-C1-51`); any generic workflow engine, which ADR-001 explicitly rejects; the untriaged-period rule (`FR-INC-20`, `T-C1-102`); the mandatory-for-assignment half of the Impact/Urgency rule, which is `T-C1-73`'s (assignment is a separate operation from a lifecycle transition).

## Acceptance criteria

**Given** an Incident in `New` with a category but no Impact or no Urgency assessed **When** a transition out of `New` is attempted **Then** it is refused with a typed domain error naming the missing assessment, and the state is unchanged.

**Given** an Incident in `New` with a category and a full assessment but no affected Service **When** a transition out of `New` is attempted **Then** it is refused with a typed domain error naming the missing Service, and the state is unchanged.

**Given** an Incident in `New` with a category, a full Impact/Urgency assessment and an affected Service **When** a transition out of `New` is attempted **Then** these two gates permit it, subject to the categorization gate (`T-C1-25`) and the other transition rules.

**Given** the state model **When** it is enumerated **Then** it contains exactly the states of `FR-INC-06`, with the three Pending reasons distinguishable from one another.

**Given** a transition the configuration does not allow **When** it is attempted **Then** it is refused with a typed domain error naming the current state and the attempted target, and nothing changes.

**Given** an Incident in `Closed` or `Cancelled` **When** a transition not explicitly permitted is attempted **Then** it is refused; a permitted reopen transition succeeds only because the configuration names it.

**Given** any successful state change **When** it commits **Then** exactly one `IncidentStateChanged` event carries actor, previous state and new state.

**Given** the implementation **When** the `incident` libraries are searched **Then** no bespoke state machine exists; the shared `StateModel` primitive is the only mechanism.
