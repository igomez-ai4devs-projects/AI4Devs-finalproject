# [C1] T-C1-86 · Scope-detection rules as configuration data

## Context

`US-C1-28` is the declared mitigation of risk **R1** — scope creep from the SCMS sporting operation into this service desk. It requires the detection rules to be **configuration data rather than hardcoded strings**, so the scope rule can be tuned as new demand patterns appear.

**Blocked by finding F25.** `FR-INC-15` says the system MUST *“reject **or** flag”* without deciding, and says nothing about where the detection patterns live. This backlog **assumes** the rules are configuration data and that reject-versus-flag is itself configured — consistent with the configuration-as-data rule of `ARCHITECTURE.md` §9. Both are **assumptions needing Product Owner confirmation**; hardcoding either would make the R1 mitigation unmaintainable.

**Phase note — finding F23, resolved.** `FR-INC-15` was unphased while the intake it protects was Phase 1; the PRD has since settled it — `FR-INC-15` is `Must`, Phase 1 (§14.3), explicitly alongside intake, and its priority was raised from `Should` for exactly this reason (§14.3's own "priority change recorded" note). `US-C1-28` and this block now carry `phase: 1 (MVP)`, correcting the stale `unphased (F9)` label (epic map finding **F17**). **F25** (reject-vs-flag, and where the patterns live) is unrelated to phasing and remains open.

## Scope

- `ScopeRule` aggregate in `libs/incident/domain`: a matching pattern, the demand category it detects — reschedule, roster change, result dispute, sanction — the configured outcome (reject or flag), and the offered path.
- The offered path is a typed reference to a Knowledge Article or a Service Catalog item; the article and the catalog item themselves belong to `C9` and `C8` and are referenced, not defined.
- TypeORM entity, mapper, migration and a seed migration carrying the demand patterns named in `FR-INC-15`.
- Configuration reload without restart, matching `T-C1-50`.
- Out of scope: the evaluation at intake (`T-C1-87`); the redirect surface (`T-C1-88`); choosing reject-versus-flag, and confirming that the rules are configuration at all — both **F25**.

## Acceptance criteria

**Given** the scope rules **When** the `incident` libraries are searched **Then** no detection pattern is hardcoded; every pattern is persisted configuration.

**Given** a rule **When** it is read **Then** it carries its demand category, its configured outcome and the path it offers.

**Given** a rule change **When** it commits **Then** the next intake evaluation honours it with no restart, and the change is published as a domain event for the audit trail.

**Given** **F25** unresolved **When** the epic is reviewed **Then** this ticket is reported as built on a stated assumption, and `FR-INC-15` is not claimed settled.
