# [C10] T-C10-09 · `libs/shared/domain` — `DomainEvent`, `EventPublisherPort` and `ClockPort`

## Context

Foundation work with no user story behind it. Source: `docs/backlog/epic-map.md` → **Foundation ownership (priced once)**, the `libs/shared/domain` row, which names `DomainEvent` explicitly; `ARCHITECTURE.md` §9 (Domain events, Time), ADR-008 and ADR-009; and finding **F14** of `user-stories.md`.

`US-C10-13` publishes `RoleAssigned` and `RoleRevoked` post-commit, and `US-C10-14` and `US-C10-16` demand timestamps from `ClockPort` rather than `new Date()`. All three need these primitives to exist first.

**Defect fixed here, on an already-implemented ticket (`e9b3bd7`).** AC2 as first written — *"grepped for `new Date(` … the only matches are inside the `ClockPort` test double"* — is unsatisfiable by any domain library that has tests: a literal grep for the substring `new Date(` also matches every spec that builds a fixture instant with `new Date(x)`, which is legitimate everywhere, specs included. Run for real against `libs/shared/domain/src`, it returns 20 matches — 1 in `fixed-clock.ts` (the double the original AC already allowed), 2 in comments citing the prohibition, and 17 in specs building date fixtures — not a regression, a criterion that was never satisfiable as literally worded. `T-C10-08`'s own AC2 already drew the right line — *"no `new Date()`"*, empty parentheses, meaning the argument-less call that reads the system clock — and is corrected below to match it: what is forbidden is the system-clock read, never constructing an instant from a value already in hand.

## Scope

- `DomainEvent` base type: event name, occurrence timestamp, actor identity, correlation identifier, immutable payload.
- `EventPublisherPort` interface — the publish contract only; the in-process dispatcher is an `apps/api` concern (`T-C10-55`).
- `ClockPort` interface returning a UTC instant, plus a deterministic `FixedClock` test double exported for unit tests.
- Jest tests covering event immutability and the fixed-clock double.
- Out of scope: any dispatcher implementation, any subscriber, any persistence. Persisting these events as audit entries belongs to `C18` (finding **F5**).

## Acceptance criteria

Mechanical checks — this ticket has no user scenario.

**Given** a `DomainEvent` instance **When** a caller attempts to mutate its payload **Then** the mutation is rejected or has no effect on the stored event.

**Given** the library's production source, excluding `*.spec.ts` **When** it is grepped for a bare `new Date()` — no arguments, the call that reads the system clock **Then** the only match is inside the `ClockPort` test double (`FixedClock`), never in `DomainEvent` or any other domain type. Constructing an instant from a value already in hand (`new Date(x)`) is unrestricted, in production code and in specs alike, and is not what this check looks for.

**Given** `EventPublisherPort` and `ClockPort` **When** they are inspected **Then** they are interfaces with no implementation and no framework import.

**Given** the library **When** `pnpm nx test shared-domain` and `pnpm nx lint shared-domain` run **Then** both pass.
