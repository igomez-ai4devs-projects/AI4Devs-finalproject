# [C10] T-C10-28 · Global JWT guard with opt-in exemption

## Context

`FR-IAM-01` states Sport ITSM exposes **no anonymous or public surface at all**, including the Knowledge Base and the Self-Service Portal. `US-C10-02` therefore requires the guard to be registered globally so that a route a developer forgot to annotate is still rejected: the default is deny and exemption is opt-in.

**Half of this ticket's original scope is gone, not just renamed.** As first written, this ticket also validated a **session record** on every request — "the session named by the token claim must exist and be active, otherwise `401`" — so a signed-out token could not be replayed. `PRD` §14.8 now forbids exactly that: no artifact may validate access against a central session record on each request. `T-C10-24`, the aggregate this check depended on, is retired. What remains is the half that never depended on it: signature and expiry verification is the whole check now, which makes this guard **simpler** than originally scoped, not smaller in importance — it is still the single global gate `FR-IAM-01` requires.

## Scope

- Passport JWT strategy plus a guard registered as a global `APP_GUARD` in `apps/api`.
- An explicit `@Public()` opt-in marker; the **only** exempt routes are sign-in (`T-C10-27`) and the liveness/readiness probes reserved by `T-C10-04`.
- The check is signature verification and expiry, full stop — no repository call, no session lookup. A valid, unexpired token is sufficient; nothing about it is checked against stored state.
- `401` responses use the `UNAUTHENTICATED` error code from `T-C10-11`; the failure is logged with the correlation identifier and **never** with the token.
- Out of scope: authorization (block C), the frontend guard (`T-C10-30`), the anonymous-surface acceptance proof (`T-C10-29`), re-authentication for privileged operations (`T-C10-59`/`T-C10-60`, a separate, per-request check that does not belong in this global guard).

## Acceptance criteria

**Given** any route other than sign-in and the health probes **When** it is called with no token **Then** the request is rejected with `401` before any use case executes.

**Given** a newly added route with no annotation at all **When** it is called anonymously **Then** it is still rejected with `401`, because the guard is global and exemption is opt-in.

**Given** an expired token and a token with a tampered signature **When** each is presented **Then** both are rejected with `401`, and the log line carries the correlation identifier and no token material.

**Given** a valid, unexpired token **When** a protected route is called **Then** the request proceeds and the resolved identity is available to the use case, with no database call made by this guard.

**Given** the guard's implementation **When** it is inspected **Then** it holds no dependency on a session repository or any stored-session concept — verifying this is what makes the retirement of `T-C10-24` provable at this layer, not just asserted in prose.
