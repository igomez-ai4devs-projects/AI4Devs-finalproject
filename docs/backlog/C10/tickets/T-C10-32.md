# [C10] T-C10-32 · `SignOutSession` use case — RETIRED

## Why this ticket is retired, not regenerated

The instruction that produced this pass asked for `T-C10-32` to be **regenerated** against `FR-IAM-08` at the device-assurance level, not retired outright — unlike `T-C10-24`, which was named obsolete as-is. This file explains why regeneration found no ticket left to write, and reports that conclusion rather than inventing scope to fill it, per the standing instruction to report a story/ticket mismatch instead of guessing.

This use case terminated the `Session` record `T-C10-24` created. With that record gone (PRD §14.8), there is nothing left for a backend use case to do on sign-out. The rewritten `US-C10-03` (`docs/backlog/C10/user-stories.md`) was read end to end for this pass, specifically looking for any acceptance criterion that implies a server call: there is none. Every criterion is stated as a property of **the device** — it discards its own credentials, it stops attaching a token to any request (including one "the browser had queued"), and a subsequent sign-in on that device acts under the new identity. The story's own rationale (FR-AUD-02 attribution integrity) is about *future* actions being correctly attributed once someone else signs in — not about recording the sign-out event itself.

Inventing a use case here — e.g. one that exists only to publish a `UserSignedOut` audit event — would be scope this story does not ask for, which is exactly what the "don't invent behavior, report it" instruction exists to prevent. The client-only replacement is `T-C10-34`.

**If this conclusion is wrong** — if there is a real reason a backend call should still happen on sign-out (a security-monitoring signal, an audit entry, something FR-AUD-02 is read to require) — that is a finding for the Business Analyst or Product Owner to confirm, not a decision this role should make unilaterally by inventing the ticket back into existence.

## Numbering

`T-C10-32` is retired and **is not reused**, for the same reason `T-C10-24` is not.
