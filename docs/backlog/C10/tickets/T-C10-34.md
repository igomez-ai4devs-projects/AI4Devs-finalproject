# [C10] T-C10-34 · Web sign-out action

## Context

`US-C10-03` ("Sign out and end usable access on the device") now traces only `FR-IAM-08`, and PRD §14.8 fixes sign-out's assurance level at **device-bounded**: the device itself must retain no usable access, and the story's own acceptance criteria describe this entirely as a client property with no server call.

**Absorbs `T-C10-32` and `T-C10-33`, both retired.** Those tickets built a `SignOutSession` use case and its HTTP adapter against a server-side `Session` record that no longer exists (`T-C10-24`, retired). Re-reading the rewritten story end to end found no acceptance criterion implying a backend call — every one of them is phrased as a property of the device: it discards its own credentials, it stops attaching a token to *any* request including one the browser had queued, and a fresh sign-in on the same device acts under the new identity. This ticket is therefore the **whole** implementation of `US-C10-03`; there is no companion backend ticket. If that turns out to be wrong — if a security or audit reason needs a server-side notification of sign-out — that is reported back to the Business Analyst / Product Owner, not invented here.

## Scope

- Sign-out action in `libs/identity-access/data-access`: clears the signal-based auth state from `T-C10-30` (token, cached identity, any derived authenticated flag) in one atomic step. **No HTTP call.**
- The token store is the single source the interceptor of `T-C10-30` reads at send time, not a value captured into an in-flight or queued request ahead of time — so a request the browser had already queued before sign-out completed is sent with **no** token once the store is cleared, and the standing global guard rejects it as unauthenticated, exactly like any other unauthenticated call. This is the mechanism behind the story's "replaying a request the browser had queued" criterion, and it is proven at this layer, not invented as a new backend check.
- Sign-out control reachable from every authenticated surface of the shell (`US-C10-03`'s own "not only one screen"), keyboard-operable and labelled for assistive technology.
- Navigation to the sign-in route on completion, with the browser history entry replaced so the back button does not return to an authenticated view.
- Out of scope: any server endpoint (none exists for this action); the inactivity and maximum-lifetime bounds (`T-C10-56`–`T-C10-58`), which are a separate device-side mechanism.

## Acceptance criteria

**Given** an authenticated agent on any authenticated surface **When** they choose sign out **Then** every credential and cached authenticated state the client held is discarded in one step, and the shell navigates to sign-in — reachable the same way from every authenticated surface, not only one.

**Given** a device on which sign-out has just completed **When** a request the browser had queued before sign-out is finally sent **Then** the interceptor attaches no token (the store was already cleared), and the request is rejected as unauthenticated like any other anonymous call — no fresh backend logic is required for this, only that the interceptor reads the store live rather than a captured value.

**Given** the user has signed out **When** they press the browser back button **Then** they are not returned to an authenticated view; the router guard of `T-C10-30` sends them to sign-in.

**Given** a signed-out device **When** anyone signs in on it afterward **Then** the action proceeds under the identity that just authenticated — this ticket does not re-verify that claim itself, it only guarantees the device holds nothing from the previous user by the time a new sign-in can happen.

**Given** the sign-out control **When** it is reached by keyboard **Then** it is focusable, has an accessible name and activates with both `Enter` and `Space`.
