# [C10] T-C10-43 · Competition and league scope grants in the domain

## Context

`US-C10-07` requires a competition grant to be a **persisted, explicitly scoped grant** in the `identity-access` domain — never inferred from a name match, a text field or a role label. `US-C10-08` needs the same for a league. Both scopes are modelled here before either predicate consumes them.

**Defect found while resolving a `DATA-MODEL.md` contradiction (verified against the current text, not superseded).** As first written, this ticket gave `ScopeGrant` no temporal validity at all — no `valid_from`, no `valid_to`. But `DATA-MODEL.md` §6.3/§20.1 declares `iam_competition_scope.valid_from` `NOT NULL`, `valid_to` nullable, a `ck_iam_competition_scope_validity` CHECK (`valid_to IS NULL OR valid_to > valid_from`), and a partial index `ix_iam_competition_scope_user … WHERE valid_to IS NULL` read on **every** scoped query (`FR-IAM-03`, `NFR-SEC-02`). Left as written, `T-C10-44` would meet two columns the domain never declared and would have to invent their meaning in the infrastructure layer — the dependency inversion the architecture forbids (adapters implement the domain's shape, they do not extend it).

`ARCHITECTURE.md` §4.2 fixes the shape this validity period must take: `DateTimeRange`, a half-open interval of UTC instants with an **optional** upper bound — absent means "still in force", exactly the `valid_to IS NULL` case — and a **strict** `to > from` check, exactly `ck_iam_competition_scope_validity`. It already exists and is green: `libs/shared/domain` (`T-C10-08`) ships `DateTimeRange.between`, `DateTimeRange.openEndedFrom(startsAt)`, the `isOpenEnded` getter, `closedAt(endsAt)` and `contains(instant)`. `ScopeGrant` is one of the three contexts named in that section as the reason the primitive earns its place in the shared kernel — it does not need a bespoke shape, only to use the one already built.

**Second defect, found correcting `T-C10-44`'s column names against `DATA-MODEL.md` §6.3/§20.1.** As first written, this ticket gave `ScopeGrant` one "target identifier" field. The canonical model has **two**: `subject_external_id` (opaque SCMS identifier, nullable) and `subject_label` (free-text fallback, nullable), guarded by `ck_iam_competition_scope_subject` — at least one present — because `R10`/`NFR-AVL-03` require the affected subject to stay capturable when the SCMS lookup is unavailable, the same fallback `ARCHITECTURE.md` §4.3 gives the `incident` context's own competition subject (`ck_incident_subject`, `DATA-MODEL.md` §8.1). Collapsing this into one field, as originally drafted, would have forced `T-C10-44` to either drop the fallback silently or invent a second column the domain never declared — the identical dependency-inversion risk the validity-period defect above already illustrates, one field over. Note this is **not** the same thing as the story's own rule that a grant is "never inferred from a name match, a text field or a role label" (`US-C10-07`) — that rule bans using free text as a matching *heuristic* at evaluation time; `subjectLabel` is an explicit, exactly-compared fallback *identifier* captured once at grant creation, not a search string.

## Scope

- `ScopeGrant` in `libs/identity-access/domain`: subject user, grant kind (competition or league), a **subject reference** — an opaque `subjectExternalId` and/or a free-text `subjectLabel` fallback, **at least one required** at construction (mirrors `ck_iam_competition_scope_subject`) — **and `validPeriod: DateTimeRange`**. A grant currently in force is constructed with `DateTimeRange.openEndedFrom(startsAt)`; `startsAt` is passed in by the caller (the application layer, via `ClockPort`) — the domain never calls `new Date()`.
- `ScopeGrant.isActiveAt(instant: Date): boolean`, delegating to `validPeriod.contains(instant)`. This is the operation the predicates of `T-C10-45`/`T-C10-46` and the port below use to decide currency; neither reaches into `DateTimeRange` directly.
- `ScopeGrantRepositoryPort`: list a user's grants **that are active at a given instant** (not "list grants" unqualified — the instant parameter is what the partial index above exists to serve efficiently), and resolve the competition set covered by a league grant.
- The `Actor` of `T-C10-38` extended to carry its resolved grants.
- Competition and league identifiers are opaque identifiers to this context — `identity-access` never imports a competition model; `subjectLabel`, when present, is opaque free text, never parsed or matched against.
- Jest unit tests for grant construction (including subject-reference combinations: id only, label only, both, neither — rejected), equality, the actor extension, and `isActiveAt` (true at and after `startsAt` while open-ended, false before it).
- Out of scope: **retiring or superseding a grant** (`DateTimeRange.closedAt`) — no story in this epic revokes a competition or league grant, so there is nothing yet to test; the primitive already supports it for when that story exists. Also out of scope: persistence (`T-C10-44`), the predicates (`T-C10-45`, `T-C10-46`).

## Acceptance criteria

**Given** a `ScopeGrant` **When** it is constructed with an explicit kind, a `validPeriod` and at least one of `subjectExternalId` / `subjectLabel` **Then** construction succeeds; **when** neither is present **then** it is rejected.

**Given** the domain library **When** it is inspected **Then** it holds no competition or league model — `subjectExternalId` and `subjectLabel` are opaque, never parsed or pattern-matched — and no `new Date(` construction; `validPeriod` is a `DateTimeRange` imported from `libs/shared/domain`.

**Given** a grant constructed with `DateTimeRange.openEndedFrom(startsAt)` **When** `isActiveAt` is evaluated at `startsAt` or any later instant **Then** it returns `true`, indefinitely, because the period has no end.

**Given** the same grant **When** `isActiveAt` is evaluated at an instant before `startsAt` **Then** it returns `false`.

**Given** an `Actor` **When** it is assembled **Then** its grants are an explicit collection, empty by default rather than absent.

**Given** the port **When** it is inspected **Then** its grant-listing operation takes an instant and returns only grants active at it, and league-to-competition resolution is declared as a separate operation, so it can be answered at evaluation time rather than frozen into the grant.
