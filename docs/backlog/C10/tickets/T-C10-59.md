# [C10] T-C10-59 · Privileged-operation declaration marker and registry

## Context

`US-C10-15` (retitled: "Prove identity again at the moment of a privileged administrative action") requires privileged operations to be satisfied **by declaration** rather than by remembering to add a check, so a newly added privileged operation inherits the rule through the same marker.

**Blocked by finding F16, now partially resolved.** The rewritten `FR-IAM-06` states the proposed set directly in the requirement text — "role grant or revocation, reference-data and policy configuration, and every operation restricted by `NFR-SEC-06`" — so this is the PRD's own list now, not a backlog assumption. **Still open:** whether every `NFR-SEC-06`-restricted screen in the eventual Admin Console counts is a judgment call at ticketing time, not settled by the wording alone, so `blocked_by: F16` stays until that enumeration is closed.

**Narrowed, not just re-phased.** As first written, this ticket also extended the `Session` aggregate of `T-C10-24` with a step-up verification timestamp and an `isStepUpValid(window, now)` decision — a stored, time-bounded authorization the rewritten story explicitly rules out: *"no guard, token claim or stored flag is specified here... what it does rule out... is any design whose observable behavior is proof-once-then-trusted for a configured window tracked in a central, per-request-checked session record."* `T-C10-24` is retired. The verification-window mechanism moves to `T-C10-60`, redesigned as a per-request check with nothing stored anywhere; this ticket keeps only the declaration marker and its registry, which never depended on a session in the first place.

## Scope

- A `@Privileged()` declaration marker readable by the application layer, and a single registry that enumerates the declared privileged operations.
- The provisional membership of that registry seeded from the PRD's own list (`FR-IAM-06`), marked in code as pending final confirmation with a reference to finding **F16** for the `NFR-SEC-06` judgment call.
- Out of scope: any enforcement (`T-C10-60`), the prompt (`T-C10-61`), any stored validity window (there is none), and any decision about the remaining `NFR-SEC-06` judgment call.

## Acceptance criteria

**Given** an operation carrying the declaration marker **When** the registry is enumerated **Then** the operation appears in it without any additional registration step.

**Given** a new privileged operation added later **When** it carries the marker **Then** it is covered by the rule with no change to the enforcement code.

**Given** the registry's source **When** it is inspected **Then** it holds no time-bounded, session-shaped or otherwise stored authorization state — its only job is naming which operations are privileged, never deciding whether a given request has proven identity recently enough.

**Given** the provisional registry **When** it is read **Then** it names finding **F16** and states that the `NFR-SEC-06` enumeration judgment call is still open, while the set itself now quotes the PRD directly rather than proposing one.
